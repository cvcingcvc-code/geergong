# Gorgon Workbench — 比赛演示脚本（60–120 秒）

> 一条指令贯穿全链路：**任务 → 路由 → 搜索 → 来源 → 计划 → 结果 → 时间线 → 完成**
> 全程离线可跑（demo 数据），每一步都诚实标注「本地处理 / AI Assisted」。

---

## 0. 准备（演示前 10 秒）

双击 `release/Gorgon-Workbench-Windows/Gorgon Workbench.exe`。

- 免安装、免 npm、免命令行：启动器会自动拉起前端与检索服务并打开窗口。
- 首次打开约 2–4 秒；窗口标题 `Gorgon Workbench`。
- 程序自带 `?demo=1` 演示模式：**桌面已预置一条比赛任务**，页面不会是空的。

---

## 1. 首页 · 一句话说清产品（0:00–0:15）

> 「Gorgon Workbench 是一个**可审计的任务工作台**：你用一句自然语言提需求，
> 它把需求拆成任务、决定用哪些工具、真的去检索、再给出计划——每一步你都能看见它做了什么。」

指一下首页：

- 顶部状态条 `AI Engine: Not connected` —— **诚实**：没配模型就明确说没连，
  不假装有 AI。
- 任务输入框 —— 演示真正要跑的指令就在下面的任务列表里。

---

## 2. 预置的比赛任务（0:15–0:25）

切到「任务」，指出那一条（它是被**幂等**预置的，重复打开不会变成两条）：

> `帮我找上海未来一周值得参加的 AI/创业活动，优先免费、适合认识开发者，并帮我制定参加计划。`

点「详情」进入任务页。

---

## 3. 运行：路由先决策（0:25–0:50）

点「**运行任务**」。任务会依次经过
`已创建 → 规划中 → 就绪 → 执行中 → 已完成`。

指「任务路由（确定性规则）」面板：

- 任务类型：**多步工作流**
- 使用工具：**✓ 智能搜索** + **✓ 本地规划**
- 判断依据：`检测到「找、活动」→ search；检测到「计划」→ plan`

> 关键点：**由确定性规则决定用哪些工具**，不是让模型自由发挥。
> 未知意图时它**不会猜**，会留空让你手动选。

然后状态变为 **已完成**，两步骤全部 completed：
**智能搜索** → **本地规划**（后者直接消费前面的检索结果）。

---

## 4. 结果与来源（0:50–1:10）

- **结果**：一份「参加计划」，含活动取舍与时间安排。
- **来源**：本次检索到的活动来源列表，每条都带 **DEMO** 徽标 ——
  演示数据就是演示数据，绝不冒充实时结果。

---

## 5. 「处理方式」——本次演示最有说服力的一页（1:10–1:35）

指「处理方式」面板：

```text
智能搜索    本地处理    Token/API：0
本地规划    本地处理    Token/API：0
共 2 个步骤 · 其中 AI 辅助 0 个 · 确定性本地处理 2 个
```

> 「这是这套系统的核心态度：**每个步骤都标明它到底是谁做的**。
> 现在这两步都是本地确定性处理，所以 Token 是 0。
> 如果某一步真的调用了大模型，这里会变成 `AI Assisted` 并显示用量；
> 模型失败时它会**降级回本地**并把降级原因写出来，而不是编一个结果。
> 而检索这一步永远不允许交给模型。」

---

## 6. 人工审核：人始终在回路里（1:35–1:50）

切到「审核中心」：

- 这里有 **真实**的提议（Proposal）：AI/引擎提出的后续动作先变成
  一条**待批准**记录，`提议 → 批准/驳回`。
- 点「批准」——它会**真的创建一个后续任务**（回到任务列表即可看到）。

> 「任何要落地成外部动作的事情，都必须先经过人的批准。
> 我们不做自动执行，也不做多智能体自动循环。」

---

## 7. 收尾（1:50–2:00）

切到「设置」，指出：

- 没有任何输入 API Key 的框 —— **密钥只从宿主环境读，永远不进前端**。
- 产品边界写得很清楚。

> 「所以它不是聊天机器人，是一个**可复现、可审计、能被信任**的任务工作台。
> 演示到这里，整条链路每一步都可核对。」

---

## 附：演示时可能被问到的问题

**Q：没连模型，那 AI 体现在哪？**
A：AI 是**按需**接入的：闸门先判断这一步值不值得用模型（长输入、抽取、规划等，
且检索/去重/校验等步骤永久禁止）。值，才调；调失败，降级回本地并写明原因。
所以「没连模型」时产品依然完整可用——这正是可审计性的前提。

**Q：搜索结果是真的吗？**
A：演示模式是**打包在程序里的 demo 数据集**，每条来源都标 `DEMO`。
切换真实检索只需在启动时指定模式，产品不会把两种数据混淆。

**Q：为什么不做多智能体 / 自动执行？**
A：那会让「谁做的决定」变得不可追溯。比赛要求的是可复现与可审计，
所以架构上刻意选择**确定性路由 + 单一写入口 + 人工批准**。

## 技术备查（讲解时可选）

| 环节 | 实现 |
| --- | --- |
| 任务状态机 | `task-model.js`（显式转移白名单） |
| 路由 | `task-router.js` 纯函数，最多 3 个工具，未知意图不猜 |
| 执行 | `task-runner.js` 是 Task 层**唯一写入口**，依赖全可注入 |
| 技能 | search / extract / summarize / plan / write（全部确定性可用） |
| AI 闸门 | `ai/eligibility.js` 纯函数 `shouldUseAI`，先硬拒绝后复杂度 |
| 降级 | cache → 确定性 → 明确失败；模型失败原因写入 metadata |
| 审核 | `proposal-model.js` 状态机 + `proposal-repository.js` 护栏 |
| 演示种子 | `lib/demo-mode.js`，幂等、可注入、可单测 |

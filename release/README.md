# Gorgon Workbench — Competition Release

**版本** `1.0.0-competition` · **构建日期** 2026-10-09 · **平台** Windows x64

---

## 这是什么

Gorgon Workbench 是一个**可审计的任务工作台**：用一句自然语言提需求，
它把需求拆成任务、**由确定性规则决定用哪些工具**、真的去检索、
再给出计划 —— 每一步你都能看见、能核对、能追溯到是谁做的。

它不是聊天机器人。核心主张是三条：

1. **确定性优先** —— 路由、状态机、执行顺序都由显式规则决定，不靠模型自由发挥。
2. **AI 按需接入** —— 有一个闸门判断「这一步值不值得用模型」；
   检索/去重/校验这类步骤**永久禁止**交给模型。模型不可用时**降级回本地并写明原因**，绝不编造。
3. **人始终在回路里** —— 任何要落地为外部动作的事情，先变成一条待批准的提议；
   没有人的批准，不会执行。

## 30 秒跑起来

1. 打开 `Gorgon-Workbench-Windows/`
2. 双击 **`Gorgon Workbench.exe`**
3. 窗口自动打开，并且**已经预置好一条比赛演示任务**

不需要安装 Node、不需要 Python、不需要命令行。

> 首次启动约 2–4 秒。若系统缺少桌面会话，程序会自动改用默认浏览器打开同一地址 —— 产品始终可用。

## 演示怎么走

完整脚本见 **`DEMO_SCRIPT.md`**（60–120 秒，含讲解词）。
最短路径：

1. 首页 → 看顶部 `AI Engine: Not connected`（**诚实**：没配模型就说没连）
2. 「任务」→ 打开预置任务（就是那条比赛指令）→ 点「**运行任务**」
3. 看「任务路由（确定性规则）」面板：**多步工作流** / **✓ 智能搜索** / **✓ 本地规划** + 判断依据
4. 状态走到 **已完成**，看到结果、来源（每条带 **DEMO** 徽标）、时间线
5. 看「**处理方式**」面板：每步标明 `本地处理` / `AI Assisted`，以及 `Token/API：0`
6. 「审核中心」→ 批准一条提议 → 它会**真的**创建一个后续任务

## 验证这个包是真能用的

打包好的 EXE 自带**无头自检**（因为它是 `--windowed` 构建，没有控制台输出）：

```powershell
cd release\Gorgon-Workbench-Windows
.\"Gorgon Workbench.exe" --selftest --report selftest.json
```

退出码 `0` 表示 8 项检查全过（前端产物、UI 服务、检索 API、应用外壳、
`/api` 反代、任务引擎已打包、演示种子已打包、窗口后端已打包）。

## 密钥与隐私

- 程序内**没有任何 API Key**，也没有输入 Key 的界面。
- 模型凭证只在运行时从**宿主环境变量**读取，**永不进入前端 bundle**
  （自检里有一项专门断言这一点）。
- 演示数据是**打包在程序内**的样例数据，每条来源都标 `DEMO`，不会与真实检索混淆。

## 已知限制

见 `RELEASE_NOTES.md` 的「已知限制」一节。简要：不联网也能完整演示；
真实检索需要宿主提供相应配置；不做自动执行、不做多智能体、不做账号/云同步。
